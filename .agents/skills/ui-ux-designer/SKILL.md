# User Research
Understanding users before designing for them.
- Identify user needs and pain points through interviews, surveys, and observation
- Base decisions on evidence, not assumptions
- Define personas and jobs-to-be-done to keep design grounded

# Information Architecture
Structuring information so users can find what they need.
- Navigation design, menus, and categorisation
- Consistent labelling and naming conventions
- Search experiences and wayfinding
- Goal: reduce cognitive load and improve findability

# Visual Design
Creating interfaces that are clean, readable, and accessible.
- **Typography:** choose readable fonts and establish a clear visual hierarchy
- **Color theory & accessibility:** apply palettes with sufficient contrast ratios; account for hover, focus, and disabled states
- **Spacing and layout:** use grids, white space, and alignment to create rhythm and structure
- **Design systems:** build and maintain reusable components, design tokens, and style guides for product cohesion

# Interaction Design
Designing how users interact with a product.
- Button behaviour, navigation patterns, and form interactions
- Micro-interactions and animations that give immediate, natural feedback
- Responsive and adaptive layouts that scale across mobile, tablet, and desktop
- Error handling that is clear, recoverable, and non-blaming
- Goal: make interactions intuitive and predictable

# User Flows & IA Mapping
Mapping how a user moves from point A to point B.
- Sketch flows before jumping to high-fidelity screens
- Identify decision points, dead ends, and happy paths
- Validate flows against real user tasks before implementation

# Analytical Skills
Using data and critical thinking to evaluate designs.
- Analyse usability test results and identify friction points
- Review user behaviour metrics (e.g. drop-off rates, rage clicks)
- Measure design effectiveness against defined success criteria
- Common tools: GA4, Mixpanel, Hotjar, session recordings

# Empathy & Advocacy
Seeing problems from the user's perspective, then representing those users in product decisions.
- Recognise user frustrations before they surface as support tickets
- Push back on feature requests that add complexity without user value
- Champion accessibility as a baseline, not an add-on

# Technical Literacy
Modern UI design overlaps with frontend engineering.
- Understand how HTML and CSS translate design intent into implementation
- Know enough about component libraries (e.g. shadcn/ui, Radix) and utility frameworks (e.g. Tailwind CSS) to bridge design-to-code handoff
- Write micro-copy that is clear, concise, and context-aware (error messages, empty states, button labels)
- Collaborate with engineers to catch implementation drift from the design spec early
